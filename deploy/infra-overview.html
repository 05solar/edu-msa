요청 흐름 & 신뢰 등급 분리

zero-trust 경계

내부 · edu-services

CODER / ADMIN (반신뢰)
  • PodSecurity baseline 강제
  • Egress 사설망 포함 허용(내부 업무)
  • 가용성 HPA + PDB + 무중단 롤링
  • RBAC edu-deployer가 이 ns에만 배포

공개 · edu-services-public

USER / 익명 / 불명 (비신뢰)
  • PodSecurity restricted 강제(비루트·캡드롭·seccomp)
  • Egress 사설망 차단(default-deny + DNS만)
  • 샌드박스 gVisor RuntimeClass(선택)
  • 비용 KEDA scale-to-zero(유휴 0)
# 요청 경로
client ──HTTPS──▶ ingress-nginx [ TLS · rate-limit · WAF ] ──▶ route ∈ { platform, internal, public }
# WAF 판정  verdict(req) = if match(OWASP-CRS) → 403 else pass   // 검증: XSS·SQLi·traversal = 403

멀티테넌트 보안 (hardening/)

신뢰 모델 기반

PodSecurity Admission

내부 baseline / 공개 restricted 강제. 루트·권한상승·특권 컨테이너 차단.

NetworkPolicy (Calico)

default-deny + DNS 허용. 공개 tier는 사설망 egress 차단(데이터 유출 방지).

ResourceQuota / LimitRange

ns별 CPU·메모리 상한. 한 서비스가 클러스터 자원 독점 방지.

안전 빌드 (Kaniko)

호스트 docker.sock 미노출. 미신뢰 repoUrl/branch 정규식 검증(주입 차단).

최소권한 RBAC

edu-deployer SA는 edu-services에 Deploy/Svc/Ingress만. 파드는 read.

gVisor RuntimeClass

공개 서비스에 사용자공간 커널 샌드박스(선택 적용).

# 가용성 불변식  live ⟺ (replicas ≥ 2) ∧ (maxUnavailable = 0) ∧ (PDB: maxUnavailable ≤ 1)
# 레지스트리 등가  pull(localhost:5001/x) ≡ push(kind-registry:5000/x)  // 동일 repo·digest
