개요 및 대응 총괄

작성 배경

  • ISMP 추진목적은 "교직원 업무경감용으로 개발된 여러 소프트웨어를 검색·공유하고, 기 구축된 AI LLM 서비스와 신규 구축 서비스를 하나의 플랫폼에서 교직원·학생·학부모·일반인이 활용"하는 플랫폼 구축입니다.
  • 현행 시스템(edu-msa)은 위 목적의 중심 축인 프로그램 저장소와 웹서비스 제공 플랫폼, 통합 인증 관문을 실동작 수준으로 구현·검증한 상태입니다.
  • 본 문서는 ISMP 핵심과제·제안요청 항목을 기준으로 구현 완료 / 부분 구현 / 구현 예정을 구분하고, 부문별 구조 도면과 기능 명세로 그 근거를 제시합니다.

현행 시스템 개요

구분내용
시스템 성격 교육청 구성원이 제작한 업무 프로그램을 저장소(레포)로 등록하면, 플랫폼이 표준 규격을 검증하고 컨테이너 서비스로 자동 배포하여 전 직원이 웹에서 즉시 사용하도록 하는 내부 포털
구성 통합 포털(웹) · 플랫폼 API · 통합 인증 서비스의 3개 응용과 2개 데이터베이스(플랫폼용·인증용 분리), 컨테이너 오케스트레이션 기반 배포 파이프라인 및 운영 스택
검증 상태 등록→검증→승인→자동배포→공개 전 과정 실동작, 기본 업무 도구 7종(6개 언어) 배포 서비스 중, 실서버(PoC 도메인) 배포 검증 완료
기술 원칙 전 구성요소 공개 소프트웨어(오픈소스) 사용, 플랫폼 코어는 CPU 전용(기존 가상화 장비 활용 가능), 기능별 독립 서비스 분리로 외부 연계 시 변경 범위 최소화

통합 인증·통합로그인 부문 (CNR-008·009)

요구사항 요지

  • 하나의 로그인으로 플랫폼과 다른 서비스를 연동하는 통합로그인 구현 방법 제시 (CNR-008)
  • 교육행정정보시스템(NEIS) 사용자 연동 및 외부 플랫폼 사용자 연동 방안 제시 (CNR-009)
  • 기 구축된 로그인 서비스를 적극 활용할 것 (사업범위 다.항)

ISMP가 요구하는 "필요 기능 우선 개발·단계적 확대" 원칙에 따라, 현행 시스템은 버전 단위의 단계 개발→검증→문서화를 반복해 왔으며 이후 단계도 동일 절차로 확장합니다.

플랫폼 코어 완성 — 구현 완료 상태

등록→검증→승인→자동배포→공개 전 과정이 실동작하며, 오토스케일·DB 고가용성·격리·관측성·원커맨드 배포까지 실서버(PoC 도메인)에서 검증을 완료하였습니다. 기본 업무 도구 7종을 서비스 중입니다.

1단계
내부망 소스 저장소(Gitea) 전환

내부망 코드 반출 불가 제약에 대응하는 단계입니다. 설치·도메인/TLS·파이프라인 자격증명·저장 이벤트 자동 재배포·예제 미러링·통합 검증의 6단계 세부 계획 수립을 완료하였으며, 소요 기간은 3.5~4일로 예상합니다(계획서 기준).

2단계
통합로그인 확장 — NEIS·교육청 SSO

인증 서비스에 SSO 콜백·계정 매핑·자동 생성을 추가합니다(토큰 소비 구간 무변경). 사용자 그룹(학생·학부모·일반인) 세분화와 비로그인 공개 화면·홈 개인화를 병행합니다.

3단계
업무용 LLM — AI 게이트웨이·전북GPT 연동

비식별(블라인드) 처리 게이트웨이를 우선 신설한 뒤 전북GPT API·내부 LLM(Ollama/vLLM)·프론티어 LLM을 연결합니다. 특화 RAG·MCP 개방은 전북GPT 과업과의 역할 분담 협의 후 착수합니다.

4단계
정부AI 연계·운영 성숙화 — 정식 개통(v1.0)

범정부 AI·AI정부실험실 커넥터를 연동하고, 시크릿 금고화(Vault/Sealed Secrets)·감사로그 등 공공 보안 지침 대응을 완성합니다. 테넌트 DB 프로비저닝 등 확장 기능 반영 후 정식 개통합니다.
